Computing statistics

Computing population genetic statistics requires a specification of what should be computed and how. Which individuals should a computation be performed on? If multiple individuals should be grouped together, how do we define these groups?

This chapter will teach you how to do this with slendr by guiding you through exercises focused on the most fundamental concepts of population genomics. The focus will be less on teach you how these concepts work (you might be already be quite familiar with) and more to give you the opportunity to learn the technicalities of R and slendr in a familiar context.

That said, the exercises have designed to provide interesting puzzles to showcase the usefulness of simulation-based exploration even in (seemingly) basic scenarios and applications, so that even readers relatively well familiar with population genomics will appreciate a new perspective on familiar topics.

Preparation

Let’s start with the following single-population model to keep things as simple as possible. Look through the code to understand what it does, then save it as slendr_statistics_single.R. Run the entire script and inspect the produced visualization to make sure your understanding is correct.

library(slendr)
init_env()

pop <- population("pop", time = 1, N = 5000)

model <- compile_model(
  populations = pop,
  generation_time = 1,
  simulation_length = 1000
)

plot_model(model)

ts <- msprime(model, sequence_length = 10e6, recombination_rate = 1e-8)

samples <- ts_names(ts)

Here’s how we can make that happen.

Exercise: Within-group(s) statistics — nucleotide diversity

The simplest possible computation we can do is to compute a statistic from a single population. As an example, let’s look at nucleotide diversity \(\pi\), implemented by a slendr function ts_diversity().

If you look at its help page under ?ts_diversity, you will see that it accepts several arguments—for now let’s focus on the first two, ts = (which is obviously a tree-sequence object, such as the one produced by the msprime() engine) and sample_sets =.

When you read the definition of nucleotide diversity, knowing that slendr simulates diploids, how would you interpret the output of ts_diversity() when you compute in on a single simulated individual, such as the indivdual with the name “pop_1”?

NoteClick to see the solution

The answer is that we get that individual’s heterozygosity—the proportion of their genome carrying heterozygous sites:

ts_diversity(ts, sample_sets = "pop_1")
# A tibble: 1 × 2
  set   diversity
  <chr>     <dbl>
1 pop_1  0.000196

Note that this is the same thing as the following command:

ts_diversity(ts, sample_sets = c("pop_1"))
# A tibble: 1 × 2
  set   diversity
  <chr>     <dbl>
1 pop_1  0.000196

Because in R, a single value is the same thing as a vector of length one (this might seem like a bit of curious trivia but it’s good to keep in mind):

"single_value" == c("single_value")
[1] TRUE
length(c("single_value"))
[1] 1
length("single_value")
[1] 1

Now run the following three commands. They look extremely similar, right? Do they produce the same value? If not, how do you interpret them?

(It turns out that patterns like these are very important for computing any kind of tree-sequence statistic with slendr, so it very much pays off to think about this, even though this looks trivial and nit-picky!)

ts_diversity(ts, sample_sets = c("pop_1", "pop_42"))
ts_diversity(ts, sample_sets = list(c("pop_1", "pop_42")))
ts_diversity(ts, sample_sets = list(pop_subset = c("pop_1", "pop_42")))
NoteClick to see the solution

The first command is supposed to demonstrate that specifying a vector of individuals’ names to a statistic which operates within a given group of samples simply computes that statistic as if each individual was its own sample:

ts_diversity(ts, sample_sets = c("pop_1", "pop_2"))
# A tibble: 2 × 2
  set   diversity
  <chr>     <dbl>
1 pop_1  0.000196
2 pop_2  0.000184

The second command features the same vector of names, but wrapped in list(). This is how you can instruct slendr to treat a given set of individuals as a group—and in this case, compute a statistic for the group as a whole. In this context, this command computes the nucleotide diversity within the given sample of two individuals from the whole population “pop”:

ts_diversity(ts, sample_sets = list(c("pop_1", "pop_2", "pop_3")))
# A tibble: 1 × 2
  set   diversity
  <chr>     <dbl>
1 set_1  0.000184

Notice that slendr assigned this “anonymous” group of individuals the name “set_1”. Because these default names can be confusing in more complex computations of more complex statistics, you can optionally specify the name of your group by providing the set of individuals as a named list instead (see the R bootcamp chapter in case you need a refresher on named lists and similar topics):

ts_diversity(ts, sample_sets = list(pop_subset = c("pop_1", "pop_2", "pop_3")))
# A tibble: 1 × 2
  set        diversity
  <chr>          <dbl>
1 pop_subset  0.000184

Of course, you can compute any statistic not only for one group of individuals, but for multiple of them. What result such computation produces depends on whether we’re computing so-called “one-way” statistics (which are computed within groups, like nucleotide diversity here) or “multi-way” statistic (which are computed between groups, like \(F_{ST}\)). For now we’ll stay with one-way statistics.

To make the “one-way” statistic concept clear, let’s practice this. Instead of computing ts_diversity() for a single group of individuals (like “pop_1” and “pop_2” above), compute this using a single ts_diversity() command on multiple subsets of individuals of increasing sizes (let’s say groups of 1, 2, 5, 10, 500 1000, and finally all individuals). Do you expect the same value of nucleotide diversity? And why?

Hint: You can obtain a random subset of a larger set of elements using the built-in R function sample(). Take a look at ?sample manual page if you need more help.

NoteClick to see the solution

Let’s first generate the subsets of individuals of different sizes. We have a number of options:

  1. We could do it “manually” like this:
# first get all names of all individuals recorded in the tree sequence
all_inds <- ts_names(ts)

# then manually create all subset names
subsets <- list(
  sample(all_inds, 1),
  sample(all_inds, 2),
  sample(all_inds, 5),
  sample(all_inds, 10),
  sample(all_inds, 500),
  sample(all_inds, 1000),
  all_inds
)
  1. Alternatively, we could do it more succinctly using this R pattern:
# first get the desired sizes of all subsets
sizes <- c(1, 2, 5, 10, 500, 1000, length(all_inds))

# then iterate over those sizes, and applying the sample() function to each
subsets <- lapply(sizes, sample, x = all_inds)
# let's also add names to the groups based on their sizes, for easier reference
names(subsets) <- sizes

Either way, these commands give us a list of vector of appropriate lengths, which we can verify like this. It’s very useful to do these sanity checks as your working on your programs, always making sure that what you want to do actually matches reality:

# apple the length() function to each element of the list
sapply(subsets, length)
   1    2    5   10  500 1000 5000 
   1    2    5   10  500 1000 5000

Now we can finally compute nucleotide diversity in each of those groups of individuals:

ts_diversity(ts, subsets)
# A tibble: 7 × 2
  set   diversity
  <chr>     <dbl>
1 1      0.000198
2 2      0.000184
3 5      0.000198
4 10     0.000199
5 500    0.000197
6 1000   0.000197
7 5000   0.000197

Perhaps not surprisingly, we don’t see much difference. After all, this is expected, because there is only one true (and normally unknown) value of nucleotide diversity of the entire population. What changes when we compute this statistic on subsets of different sizes is the stochastic noise.

We’ll see a bit more on how to control (and quantify) the noise using simulations a little bit later.

Exercise: Parameter estimation — \(N_e\)

In practical research, we often use different software methods or statistics to estimate some value of interest. In our context—to use a very simple toy example to demonstrate a simulation-based approach in a familiar context—let’s look at a measure of the population size called effective population size, or \(N_e\).

From a bit of background theory of population genetics, we know that we can obtain an estimate of \(N_e\) from nucleotide diversity, which we just computed. Specifically, neutral theory of molecular evolution posits that an idealised diploid population will have a pairwise nucleotide diversity equal to

\[\theta = 4 N_e \mu,\]

where \(\mu\) is the mutation rate. Using simple algebra, this gives us an estimate for \(N_e\) in the form of

\[N_e = \frac{\theta}{4 \mu}.\]

How well does this estimator perform under different scenarios?

If you’re familiar with population genetics, this has all sorts of obvious answers, but let’s demonstrate how we can benchmark this using simulations, hopefully establishing a useful slendr recipe which you will be able to use very often in all kinds of contexts (some of the more complex ones will be demonstrated later in this workshop).

Start by computing a data frame df containing the nucleotide diversity value for every single individual in your tree sequence. Then, use the equation above establishing how to estimate \(N_e\) from nucleotide diversity to add a new column Ne_estimated to this data frame containing the \(N_e\) inferred from this model. Do you get the correct value?

Hint: Remember that you know the true \(N_e\) in your model — it’s the N value in your simulation script! That’s the most powerful thing about simulations — they allow you to establish a ground truth, and benchmark various methods against it!

NoteClick to see the solution

Let’s get the data frame with the value of \(\pi\) first:

df <- ts_diversity(ts, list(all = ts_names(ts)))
df
# A tibble: 1 × 2
  set   diversity
  <chr>     <dbl>
1 all    0.000197

Then add the inferred \(N_e\) according to the equation above:

df$Ne_estimated <- df$diversity / (4 * 1e-8)
df
# A tibble: 1 × 3
  set   diversity Ne_estimated
  <chr>     <dbl>        <dbl>
1 all    0.000197        4919.

Of course, benchmarking any method based on a single simulation of a single number doesn’t make sense — so now let’s move things one step forward.

Exercise: Generalizing the simulation

Suppose we need to evaluate how our statistic of interest (here the estimator of \(N_e\)) behaves under different parameters, different, models, different data, etc.

The first instinct of most people would be to just make a copy of the original script, modify it a bunch of times, and re-run the modifications as needed. This works, but is almost always the wrong approach. The correct way to do this is to generalize our code into a self-contained function.

Let’s break this down into individual steps (in software engineering, this process of modifying code and improving it is called “refactoring”).

First, save your script slendr_statistics_single.R into a new file called slendr_statistics_Ne.R. We’ll be working on our improvements in this new file.

Then, program a function called sim_constant, which will accept a single argument Ne_true, and will “wrap around” the following bits of code:

  1. **the slendr demographic model code which compiles the model object,

  2. **the command simulating a ts object from the given model,

  3. the commands creating the df data frame with nucleotide diversity,

  4. the inference of Ne_estimated from nucleotide diversity,

  5. adding a column to df called Ne_true and assigning it the Ne_true argument of your function.

Your function should return this df object as its output.

When you’re done, the code doing 1.-4. above should be gone from your script, entirely replaced by this function.

Hint: If you need help, you can use the following template

NoteClick to see the template 
sim_constant <- function(model) {
  # move the bits of code doing 1.-4. inside this function

  return(df)
}
NoteClick to see the solution

Here’s how my entire slendr_statistics_Ne.R looks like:

library(slendr)
init_env()

sim_constant <- function(Ne_true) {
  pop <- population("pop", time = 1, N = Ne_true)
  
  model <- compile_model(
    populations = pop,
    generation_time = 1, simulation_length = 1000
  )

  ts <-
    msprime(model, sequence_length = 1e6, recombination_rate = 1e-8) %>%
    ts_mutate(mutation_rate = 1e-8)

  samples <- ts_names(ts)
  
  df <- ts_diversity(ts, list(all = samples))

  df$Ne_estimated <- df$diversity / (4 * 1e-8)

  df$Ne_true <- Ne_true
  
  df
}

To test your function, restart your R session (in RStudio go to Session -> Restart R), then run your entire script. Then, test your function in the R console by running it for different values of \(N_e\) (for instance, type sim_constant(100), sim_constant(1234),sim_constant(20000)`, etc.). Each of your function calls should produce a data frame with the appropriate value of \(\pi\) and the estimated \(N_e\).

Doing all this extra programming work might seem like unnecessary bother. After all, by writing the function, you’ve basically written even more code! But the pay off comes later, as you will see. Custom functions are absolutely critical for efficient, reproducible science. They eliminate copy-pasted bug-prone code and make it much easier to explore ideas, test parameters, and explore various models. In this workshop, you’ll soon see how often I force you to write custom functions—hopefully, by the end you will appreciate why I did this!

df_const <- map_dfr(c(1000, 2000, 3000, 4000, 5000, 10000, 15000, 20000), sim_constant)

This is probably the best example of how to use these kinds of simulations in practice. Again, nucleotide diverisity-based \(N_e\) estimation and its benchmarking across a range of parameters really is a toy example, but this idea extends to many other settings:

  • benchmarking of IBD accuracy across different gene-flow scenarios

  • validating qpAdm inference results for various possible admixture graphs

  • testing the robustness of local ancestry inference methods (LAI) and admixture dating inference as a function of admixture times and proportions

  • understanding how PCA differs for different sample sizes from different populations

… and many others. All of these things are something you’ll be able to play with in the freeform sessions at the end, but for now, let’s carry on!

Exercise: Comparing multiple models

Let’s suppose we want to see how robust our statistic of interest (in this toy example, nucleotide divertisity, \(\pi\)) is to a choice of the underlying demographic model. In the previous exercise, we worked with using \(\pi\) to estimate the effective population size of a population under study (\(N_e\)) and verified that it works very well for a model of a long-term constant population size.

How about when we introduce a bottleneck into our model? How well does our \(N_e\) estimate work in such case?

Build a new model of a single population “pop”, again starting with \(N_e\) of 5000, then introduce a bottleneck using the function resize() which will set the size of the population to the given value Ne at time 800. You can again start by writing a couple of lines of code implementing such model, perhaps setting the bottleneck to \(N_e\) of 500, and once you have it, wrap it around in a function simulate_bottle(Ne), just like you did in the previous exercise.

pop <- population("pop", time = 1, N = 5000) %>% resize(N = 500, time = 500)

model <- compile_model(
  populations = pop,
  generation_time = 1, simulation_length = 1000
)

plot_model(model, proportions = TRUE)
simulate_bottle <- function(Ne) {
  pop <- population("pop", time = 1, N = 5000) %>%  resize(N = Ne, time = 500)
  
  model <- compile_model(
    populations = pop,
    generation_time = 1, simulation_length = 1000
  )
  
  df <- compute_pi(model)

  # add annotation for downstream analyses
  df$Ne_true <- Ne

  df
}

We can see that even a drastic population bottleneck such as the one we programmed does not actually reduce the observed levels of nucleotide diversity that much! As a result, our \(N_e\) estimate is very wrong—we consistently estimate it at the level of 5000 (i.e., the size prior to the bottleneck), regardless of the true size of the population after the bottleneck.

What this means that estimating \(N_e\) from nucleotide diversity (which is very often done in population genetics) only works reliably in a population which has reached a long-term stable effective size.

We will see about a more robust method to do this in a later exercise.

library(ggplot2)
library(purrr)

df_bottle <- map_dfr(c(1000, 2000, 3000, 4000, 5000, 10000, 15000, 20000), simulate_bottle)

ggplot(df_bottle, aes(Ne_true, Ne_estimated)) +
  geom_point() +
  geom_hline(yintercept = 5000, color = "red", linetype = "dashed") +
  ggtitle("True Ne vs Ne estimated from nucleotide diversity (bottleneck model)") +
  ylim(0, 10000)

Exercise: Segregating sites and sequencing effort

Motivation: Single model, repeated computation on a subset of tree-sequence samples.

What if you wanted to get a good idea of a genetic diversity in your population, or another summary statistic?

Bonus exercise: Your own model

If you got all the way here while the others are still working on their solutions, here’s a bonus exercise for you.

Take a demographic model of an organism or a population which is of your interest in your own research (either your own model or a model you know from the literature) and program it with slendr. Feel free to be as detailed (or not) as possible, but don’t worry about accuracy of various parameters. The point is to practice building a model from scratch. Then, compute the basic summary statistics introduced in this chapter on simulations from your model. Do the results match what you know, either from your research or from the literature? If not, what could be the problem?

If these statistics aren’t particularly interesting or relevant for your research, don’t despair. Again, the point is to practice, but even then, you’ll have plenty of opportunities to compute more interesting things throughout this course, particularly during the “freeform” sessions at the very end.
