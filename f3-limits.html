“Outgroup” \(f_3\)

Note: The \(f_3\) statistic is traditionally expressed as \(f_3(A, B; C)\), where C represents the outgroup. Unfortunately, in tskit the outgroup is named A, with B and C being the pair of samples from which we trace the length of branches towards the outgroup, so the statistic is interpreted as \(f_3(B, C; A).\)

Whenever we want to evaluate the behavior of some statistic of interest under a range of demographic scenarios and across different model parameters, it’s always useful to first establish a skeleton structure with concrete values of model parameters, before we wrap it in a dedicated function.

Let’s do this here too.

compute_outgroup_f3 <- function(tsplit) {
    outgroup <- population("outgroup", N = 1000, time = 10000)
    X <- population("X", N = 1000, time = tsplit, parent = outgroup)
    Y <- population("Y", N = 1000, time = tsplit, parent = outgroup)
    
    model <- compile_model(list(outgroup, X, Y), generation_time = 1)

    ts <- msprime(model, sequence_length = 10e6, recombination_rate = 1e-8) %>% ts_mutate(mutation_rate = 1e-8)

    samples <- ts_names(ts, split = TRUE)
    
    ts_f3(ts, A = samples["outgroup"], B = samples["X"], C = samples["Y"]) %>% mutate(tsplit = tsplit)
}

Exercise: \(f_3\) statistic as a linear combination of \(f_2\) statistics

You might have learned that any complex \(f\)-statistic can be expressed as a linear combination of multiple \(f_2\) statistics (which represent simple branch length separating two lineages). Verify that this is the case by looking up equation (20b) in this amazing paper and computing an \(f_3\) statistic for any arbitrary trio of individuals of your choosing using such linear combination of \(f_2\) statistics.

Hint: Here’s that equation in a schematic form

      f3(A, B; C) = f2(A, C) + f2(B, C) - f2(A, B) / 2
NoteClick to see the solution 
# standard f3
ts_f3(ts, B = "AFR_1", C = "AFR_2", A = "CHIMP_1")

# a "homemade" f3 statistic as a linear combination of f2 statistics
# f3(A, B; C) = f2(A, C) + f2(B, C) - f2(A, B) / 2
homemade_f3 <- (
  ts_f2(ts, A = "AFR_1", B = "CHIMP_1")$f2 +
  ts_f2(ts, A = "AFR_2", B = "CHIMP_1")$f2 -
  ts_f2(ts, A = "AFR_1", B = "AFR_2")$f2
) / 2

homemade_f3

You can see that the ts_f3() implementation gives basically the same value as our “homemade” implementation based on a linear combination of \(f_2\) statistics, just as predicted by the underlying math.

“Admixture” \(f_3\)

Now let’s explore the application of the \(f_3\) statistic in its other common use, which is an admixture test. To do this, you will need to expand our baseline population model a little bit.

In our model, we still keep the population outgroup, but the X and Y population now merge at a time tmix to form a population mix. Note that due to the way in which slendr currently implements population merges, you will first need to program the split of mix from X at time tmix - 1, followed at time tmix (i.e., immediately in the following generation) by admixture from U at some defined proportion proportion. To approximate the idea of a population merge as closely as possible within the constraints of the slendr interface, program this admixture event so that it ends after a single generation (i.e., it should end at time tmix + 1).

library(slendr)
init_env()

library(dplyr)   # manipulating tabular data
library(ggplot2) # data visualization
library(purrr)   # convenient looping functions
tmix <- 2000
prop <- 0.1
Ne <- 5000

outgroup <- population("outgroup", N = 5000, time = 10000)
x <- population("x", N = 5000, time = 5000, parent = outgroup)
y <- population("y", N = 5000, time = 5000, parent = outgroup)
mix <- population("mix", N = Ne, time = tmix + 1, parent = x)

gf <- gene_flow(from = y, to = mix, start = tmix, end = tmix - 1, proportion = prop)

model <- compile_model(list(outgroup, x, y, mix), gene_flow = gf, generation_time = 1)

plot_model(model, order = c("outgroup", "x", "mix", "y"), proportions = TRUE)

Exercise

Before we start digging into the limitations of the \(f_3\) statistic as a metric for admixture detection, let’s first create a self-contained function which generalizes our baseline model across three main parameters of interest: the admixture time tmix, the admixture proportion prop, and the effective population size of the admixed population Ne:

compute_admix_f3 <- function(tmix, prop, Ne) {
  outgroup <- population("outgroup", N = 5000, time = 10000)
  x <- population("x", N = 5000, time = 5000, parent = outgroup)
  y <- population("y", N = 5000, time = 5000, parent = outgroup)
  mix <- population("mix", N = Ne, time = tmix + 1, parent = x)

  gf <- gene_flow(from = y, to = mix, start = tmix, end = tmix - 1, proportion = prop)
  
  model <- compile_model(list(outgroup, x, y, mix), gene_flow = gf, generation_time = 1)

  schedule <- schedule_recording(model, times = 0, list(x, 5), list(y, 5), list(mix, 25))

  ts <- msprime(model, sequence_length = 25e6, recombination_rate = 1e-8, schedule = schedule) %>% ts_mutate(mutation_rate = 1e-8)

  samples <- ts_names(ts, split = TRUE)

  ts_f3(ts, A = samples["mix"], B = samples["x"], C = samples["y"]) %>% mutate(tmix = tmix, prop = prop, Ne = Ne)
}

From the trend presented by the trajectory of expected \(f_3\) values as a function of the admixture time, we can see that the statistic appears to loose power to detect admixture around 1000 generations “before present” (BP).

Under which conditions would the \(f_3\) statistic gain more power?

In conclusion, we can confirm that the amount of drift (represented by the Ne parameter) really is what determines whether or not can \(f_3\) detect admixture for a given model (represented by a fixed tmix time and prop admixture proportion). In fact, once we reach a certain size of the admixed population, the \(f_3\) value reaches a stable level below zero.
